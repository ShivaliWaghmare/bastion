Security controls

Every control below is live in this app. Each card points to the file that implements it.

12 active

Password hashing

scrypt (memory-hard) with a unique salt per user, constant-time comparison, and NIST 800-63B length + blocklist policy.

src/security/password.jsA02 · A07

Encryption at rest

Notes and 2FA secrets are sealed with AES-256-GCM. Associated data binds each ciphertext to its record and owner.

src/security/encryption.jsA02

Two-factor auth

RFC 6238 TOTP with ±30 s drift tolerance and replay protection. QR code generated server-side, secret encrypted.

src/security/totp.jsA07

Hardened sessions

256-bit IDs, HMAC-signed HttpOnly + SameSite=Strict cookies, rotation on login, idle and absolute timeouts.

src/lib/sessions.jsA07

CSRF defence

Synchronizer token, Origin check and Fetch-Metadata rejection, layered on top of SameSite cookies.

src/security/csrf.jsA01

Content Security Policy

Only same-origin scripts and styles — no inline code, no eval. Plus anti-framing, nosniff and a strict referrer policy.

src/security/headers.jsA05

Access control

Every note query is scoped to its owner (no IDOR). Admin routes check roles server-side; pages are guarded too.

src/routes/notes.jsA01

Brute-force protection

Per-IP rate limits with standard RateLimit headers, plus per-account lockout after five consecutive failures.

src/security/rateLimit.jsA07

Input validation

Strict allow-list schemas reject unknown fields, wrong types and prototype-pollution keys. Bodies capped at 32 KB.

src/validation.jsA03 · A08

XSS-safe rendering

The UI builds DOM with textContent only — no innerHTML anywhere. Try saving <img src=x onerror=alert(1)>.

public/static/js/common.jsA03

No user enumeration

Identical errors and equalised timing whether a username exists or not, including for locked accounts.

src/routes/auth.jsA07

Audit logging

Failed logins, lockouts, CSRF rejections, IDOR attempts and admin actions are recorded — never passwords or content.

src/audit.jsA09
